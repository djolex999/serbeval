Chose **srb_idioms** as task #2: tests Serbian-specific lexical knowledge that doesn't transfer from English, pairs well with grammar.
- 2026-06-13: Pinned **lm-eval==0.4.12** (latest stable on PyPI today) as "the pinned harness version".
- 2026-06-13: No ANTHROPIC_API_KEY / `ant` profile / keychain credential on this machine → generate/selfcheck/smoke-run are fully implemented + mock-tested; live invocations left as exact documented commands (HANDOFF.md). Did NOT stop to ask, per autonomy rules.
- 2026-06-13: All tasks use `output_type: generate_until` + regex letter extraction (not `multiple_choice`/loglikelihood) because Anthropic chat APIs expose no logprobs.
- 2026-06-13: Seed items authored in-session via parallel author agents, then adversarially verified by independent verifier agents (gold uniquely correct, distractors plausible-but-wrong, natural Serbian); failures fixed or dropped. All items remain `verified: false` pending the maintainer's human pass.
- 2026-06-13: Seed srb_grammar/srb_idioms items use Latin script (dominant in digital Serbian); script-sensitivity is covered separately by srb_cyrillic_agreement's paired items.
- 2026-06-13: MCQ labels are A/B/C/D (not А/Б/В/Г) even in Cyrillic items — keeps the answer-extraction regex script-independent.
- 2026-06-13: Default model for generation/selfcheck CLIs is claude-opus-4-8 (quality of authored items matters most); smoke run targets claude-haiku-4-5 per the brief. Both configurable via --model.
- 2026-06-13: lm-eval loads datasets via HF `json` loader with relative `data_files` → commands must run from repo root (documented in README).
- 2026-06-13: selfcheck keep-rule: keep a candidate only if all 3 re-answers agree with each other AND with the gold label; rejects go to discarded.jsonl with a reason. Strictest reading of "discard disagreements".
- 2026-06-13: lm-eval Anthropic adapter is `anthropic-chat` (confirmed in 0.4.12 MODEL_REGISTRY: anthropic-chat / anthropic-chat-completions / anthropic-completions). README/results use `anthropic-chat`.
- 2026-06-13: Seed authoring done via Workflow (multi-agent). First run failed: every verify/repair agent stalled on the then-default `fable-5[1m]` model + a null-guard bug. Re-ran on `opus-4-8[1m]` with a hardened, fully null-guarded script (repair phase wrapped so it can never lose first-pass items). Yielded 91 verified-pass items → 50 grammar + 30 idioms after mechanical cleanup (dedupe + reject mixed-script). Dropped items + reasons saved to data/<task>/discarded.jsonl.
- 2026-06-13: Mechanical cleanup rejects any srb_grammar/srb_idioms item whose Latin text contains Cyrillic letters — a few generated idiom distractors embedded Cyrillic as the "wrong" form, which is off-pattern (a model could flag the odd script without knowing the idiom) and violates clean-script convention.
- 2026-06-14: srb_cyrillic_agreement items are easy, factual, script-independent questions (math/geography/nature/general). Rationale: the task measures script *consistency*, so a Latin-right/Cyrillic-wrong result must isolate script handling, not difficulty. Hard items would confound the two.
- 2026-06-14: Latin→Cyrillic done by a tested deterministic transliterator (digraph-aware: lj/nj/dž). Safe only for controlled vocabulary (avoids nadž-/inj- morpheme-boundary traps); base items chosen accordingly. A/B/C/D labels stay Latin and are added at prompt time, so stored choices transliterate cleanly.
- 2026-06-14: cyrillic_agreement uses custom `process_results` (returns exact_match + a (pair_id, correct) tuple) and a custom `pair_agreement` aggregation. lm-eval 0.4.12 supports this cleanly (slow test + dummy run both pass), so it's a formal harness task — NOT the post-processing-script fallback. Letter extraction is duplicated inside utils.process_results so the pair metric is correct regardless of filter-pipeline ordering.
- 2026-06-14: ruff ignores RUF001/RUF002/RUF003 (ambiguous Latin/Cyrillic look-alikes) project-wide — intentional for a Serbian benchmark; scripts/*.py ignore E501 (inline data tables).
- 2026-06-14: Smoke run (brief item #3) done with lm-eval's built-in `dummy` model, not claude-haiku-4-5 — no ANTHROPIC_API_KEY on this machine. This still validates the full pipeline produces real numbers (both metrics aggregate). Live haiku command documented in results/README.md as the next step.
- 2026-06-14: mypy gate scoped to `src` (per CLAUDE.md `mypy src`); lm_eval_tasks/utils.py and one-shot scripts/ are not under strict typing.
- 2026-08-06: `serbeval review` treats a script pair as ONE review unit — verify/reject applies to both members atomically (rejecting one side would break pair integrity that validate_dataset enforces).
- 2026-08-06: review rejects write the FULL item dump + dropReason:"human-review" + reasons:[...] to discarded.jsonl — superset of the seed-workflow row shape (task/category/question/reasons/dropReason), so the file stays heterogeneous-but-greppable and rejects are recoverable.
- 2026-08-06: review saves items.jsonl after EVERY decision (not on exit) — a 110-item human session will be interrupted; losing one keypress is acceptable, losing a session is not.
- 2026-08-06: `serbeval report` picks the newest results_*.json per run dir by filename (lm-eval names files with ISO timestamps → lexicographic max == newest); metric keys parsed as "metric,filter" with "_stderr" pairing.
- 2026-08-06: post-build adversarial workflow (26 opus agents) confirmed 17 findings → fixed: save_items is now ATOMIC (tmp + os.replace — an interrupt mid-write can no longer truncate curated items.jsonl); review catches Ctrl-C only at prompts (never around writes); reject appends to discarded.jsonl BEFORE rewriting items.jsonl (crash leaves the item recoverable in both files, never in neither); 'q' still runs the closing integrity check; duplicate ids refuse the session; external mid-session file edits abort with FAIL; report discovers results_*.json RECURSIVELY (lm-eval writes an extra <model_name_sanitized> dir below --output_path) and skips corrupt files with a warning; adapter names (hf/dummy/anthropic-chat/...) never become the model label; stats survives one broken items.jsonl.
- 2026-09-02: Added optional `difficulty` (easy/medium/hard, default None) to EvalItem rather than a required field — the 110 seed items predate it and a null tier simply drops out of by-tier breakdowns. Pair integrity now requires both scripts of a pair to share a difficulty, else a script-gap-by-tier number would split one pair across two tiers.
- 2026-09-02: Tagged all 30 srb_cyrillic_agreement items `easy` — they were authored as deliberately easy factual questions (see 2026-06-14), so the tier records what was already true and makes the by-tier gap breakdown functional once harder pairs are added.
- 2026-09-02: `serbeval lint` is a SEPARATE advisory command that always exits 0, not part of `validate`. validate = well-formed (gates CI), lint = good (a judgement call, thresholds are heuristics). Folding them would make the pass/fail line ambiguous and turn the repo red on the existing seed set.
- 2026-09-02: lint classifies distractors by counting *error dimensions* (lexical substitutions + whether word order changed), NOT by difflib region count. A naive sequence diff scores a moved token as delete+insert, which mislabelled every clitic-placement distractor in `enklitike` as "two stacked errors"; after the fix that category scores 0.93 mean instead of 0.00. Word order is one error dimension.
- 2026-09-02: lint's `gold-length-outlier` requires gold to differ from every distractor by >=30% of mean choice length, not merely to be the longest/shortest. Rank alone fires ~50% of the time by chance on 4 choices — the first version flagged 14/30 idioms, i.e. pure noise; with the margin it flags 8.
- 2026-09-02: lint's variant/semantic shape is DECLARED per task, not inferred from choice overlap. An item whose distractors are all garbage has the same low mutual overlap as a well-built idiom item, so pure inference let the worst items escape analysis by passing as semantic. Overlap detection remains only as a fallback for unknown tasks.
- 2026-09-02: `serbeval report` uses the Wilson score interval, not the normal approximation — benchmark accuracies sit near 0/1 often enough that the normal interval yields bounds outside [0,1] and poor coverage at n=30..50. The statistics derive from the `--log_samples` JSONL, whose rows carry the full item as `doc`, so no join back to data/ is needed.
- 2026-09-02: The v0.3 markdown-table report and the CI/rankability report were developed in parallel (the former uncommitted on main, the latter on a worktree branch) and were MERGED into one `report` command rather than kept as two: the table always works, the statistics attach when per-sample logs exist. `load_runs` reuses `_model_name` so both halves label a model identically. A run without `--log_samples` prints the table plus a note explaining the missing intervals — never a bare table that invites ranking.
- 2026-09-02: Deliberately did NOT add an LLM-backed plausibility pass to lint. The repo already carries two implemented-but-never-run LLM commands (generate, selfcheck); a third speculative one before any API key exists is unjustified. Semantic plausibility is documented as a stated limitation instead.
- 2026-09-02: Added `srb_grammar_cloze` as a PROTOTYPE (20 items) rather than converting srb_grammar wholesale — the point is to measure whether cloze is harder before investing in 300 items. Cannot be answered without an API key; dummy run only proves the harness plumbing.
- 2026-09-02: Cloze items use a separate `ClozeItem` model, not a widened `EvalItem`. EvalItem's 4-choices invariant is load-bearing for the MCQ tasks and relaxing it would weaken validation for all three existing tasks.
- 2026-09-02: `ClozeItem.answers` is a LIST of accepted forms. Serbian norm has genuinely contested cases, and the seed build dropped 20 items partly for that reason; accepting every defensible form keeps such items usable instead of forcing an arbitrary reading.
- 2026-09-02: Cloze scoring normalizes case and punctuation but NEVER folds č/ć/ž/š/đ — orthography is part of what the benchmark tests, so folding them would score a misspelling as correct.
- 2026-09-02: lm_eval_tasks/utils.py IMPORTS serbeval.cloze for cloze scoring instead of duplicating it (unlike MCQ letter extraction, which is deliberately duplicated). Which characters may be folded is a correctness-critical judgement; two copies would drift silently and change scores.
