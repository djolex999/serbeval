- 2026-06-14: srb_cyrillic_agreement items are easy, factual, script-independent questions (math/geography/nature/general). Rationale: the task measures script *consistency*, so a Latin-right/Cyrillic-wrong result must isolate script handling, not difficulty. Hard items would confound the two.
- 2026-06-14: Latin→Cyrillic done by a tested deterministic transliterator (digraph-aware: lj/nj/dž). Safe only for controlled vocabulary (avoids nadž-/inj- morpheme-boundary traps); base items chosen accordingly. A/B/C/D labels stay Latin and are added at prompt time, so stored choices transliterate cleanly.
- 2026-06-14: cyrillic_agreement uses custom `process_results` (returns exact_match + a (pair_id, correct) tuple) and a custom `pair_agreement` aggregation. lm-eval 0.4.12 supports this cleanly (slow test + dummy run both pass), so it's a formal harness task — NOT the post-processing-script fallback. Letter extraction is duplicated inside utils.process_results so the pair metric is correct regardless of filter-pipeline ordering.
- 2026-06-14: ruff ignores RUF001/RUF002/RUF003 (ambiguous Latin/Cyrillic look-alikes) project-wide — intentional for a Serbian benchmark; scripts/*.py ignore E501 (inline data tables).

This still validates the full pipeline produces real numbers (both metrics aggregate). Live haiku command documented in results/README.md as the next step.
- 2026-06-14: mypy gate scoped to `src` (per CLAUDE.md `mypy src`); lm_eval_tasks/utils.py and one-shot scripts/ are not under strict typing.
- 2026-08-06: `serbeval review` treats a script pair as ONE review unit — verify/reject applies to both members atomically (rejecting one side would break pair integrity that validate_dataset enforces).
- 2026-08-06: review rejects write the FULL item dump + dropReason:"human-review" + reasons:[...] to discarded.jsonl — superset of the seed-workflow row shape (task/category/question/reasons/dropReason), so the file stays heterogeneous-but-greppable and rejects are recoverable.
- 2026-08-06: review saves items.jsonl after EVERY decision (not on exit) — a 110-item human session will be interrupted; losing one keypress is acceptable, losing a session is not.
- 2026-08-06: `serbeval report` picks the newest results_*.json per run dir by filename (lm-eval names files with ISO timestamps → lexicographic max == newest); metric keys parsed as "metric,filter" with "_stderr" pairing.
- 2026-08-06: post-build adversarial workflow (26 opus agents) confirmed 17 findings → fixed: save_items is now ATOMIC (tmp + os.replace — an interrupt mid-write can no longer truncate curated items.jsonl); review catches Ctrl-C only at prompts (never around writes); reject appends to discarded.jsonl BEFORE rewriting items.jsonl (crash leaves the item recoverable in both files, never in neither); 'q' still runs the closing integrity check; duplicate ids refuse the session; external mid-session file edits abort with FAIL; report discovers results_*.json RECURSIVELY (lm-eval writes an extra <model_name_sanitized> dir below --output_path) and skips corrupt files with a warning; adapter names (hf/dummy/anthropic-chat/...) never become the model label; stats survives one broken items.jsonl.
- 2026-09-02: Added optional `difficulty` (easy/medium/hard, default None) to EvalItem rather than a required field — the 110 seed items predate it and a null tier simply drops out of by-tier breakdowns. Pair integrity now requires both scripts of a pair to share a difficulty, else a script-gap-by-tier number would split one pair across two tiers.
- 2026-09-02: Tagged all 30 srb_cyrillic_agreement items `easy` — they were authored as deliberately easy factual questions (see 2026-06-14), so the tier records what was already true and makes the by-tier gap breakdown functional once harder pairs are added.
- 2026-09-02: `serbeval lint` is a SEPARATE advisory command that always exits 0, not part of `validate`. validate = well-formed (gates CI), lint = good (a judgement call, thresholds are heuristics). Folding them would make the pass/fail line ambiguous and turn the repo red on the existing seed set.
- 2026-09-02: lint classifies distractors by counting *error dimensions* (lexical substitutions + whether word order changed), NOT by difflib region count. A naive sequence diff scores a moved token as delete+insert, which mislabelled every clitic-placement distractor in `enklitike` as "two stacked errors"; after the fix that category scores 0.93 mean instead of 0.00. Word order is one error dimension.
- 2026-09-02: lint's `gold-length-outlier` requires gold to differ from every distractor by >=30% of mean choice length, not merely to be the longest/shortest. Rank alone fires ~50% of the time by chance on 4 choices — the first version flagged 14/30 idioms, i.e. pure noise; with the margin it flags 8.
- 2026-09-02: lint's variant/semantic shape is DECLARED per task, not inferred from choice overlap. An item whose distractors are all garbage has the same low mutual overlap as a well-built idiom item, so pure inference let the worst items escape analysis by passing as semantic. Overlap detection remains only as a fallback for unknown tasks.
- 2026-09-02: `serbeval report` uses the Wilson score interval, not the normal approximation — benchmark accuracies sit near 0/1 often enough that the normal interval yields bounds outside [0,1] and poor coverage at n=30..50. The statistics derive from the `--log_samples` JSONL, whose rows carry the full item as `doc`, so no join back to data/ is needed.
- 2026-09-02: The v0.3 markdown-table report and the CI/rankability report were developed in parallel (the former uncommitted on main, the latter on a worktree branch) and were MERGED into one `report` command rather than kept as two: the table always works, the statistics attach when per-sample logs exist. `load_runs` reuses `_model_name` so both halves label a model identically. A run without `--log_samples` prints the table plus a note explaining the missing intervals — never a bare table that invites ranking.
- 2026-09-02: Deliberately did NOT add an LLM-backed plausibility pass to lint. The repo already carries two implemented-but-never-run LLM commands (generate, selfcheck); a third speculative one before any API key exists is unjustified. Semantic plausibility is documented as a stated limitation instead.
- 2026-09-02: Added `srb_grammar_cloze` as a PROTOTYPE (20 items) rather than converting srb_grammar wholesale — the point is to measure whether cloze is harder before investing in 300 items. Cannot be answered without an API key; dummy run only proves the harness plumbing.
- 2026-09-02: Cloze items use a separate `ClozeItem` model, not a widened `EvalItem`. EvalItem's 4-choices invariant is load-bearing for the MCQ tasks and relaxing it would weaken validation for all three existing tasks.
- 2026-09-02: `ClozeItem.answers` is a LIST of accepted forms. Serbian norm has genuinely contested cases, and the seed build dropped 20 items partly for that reason; accepting every defensible form keeps such items usable instead of forcing an arbitrary reading.
- 2026-09-02: Cloze scoring normalizes case and punctuation but NEVER folds č/ć/ž/š/đ — orthography is part of what the benchmark tests, so folding them would score a misspelling as correct.
- 2026-09-02: lm_eval_tasks/utils.py IMPORTS serbeval.cloze for cloze scoring instead of duplicating it (unlike MCQ letter extraction, which is deliberately duplicated). Which characters may be folded is a correctness-critical judgement; two copies would drift silently and change scores.
- 2026-09-02: Added `serbeval mine` — cloze items generated from a morphologically annotated CoNLL-U corpus instead of authored by Claude. Removes the bootstrap problem (model writing its own exam), makes the gold form human-annotated rather than model-proposed, and scales without an API key. Validated on UD_Serbian-SET: 453 items, validate clean.
- 2026-09-02: Usable prepositions are COMPUTED from the corpus (≥95% single-case purity, ≥20 attestations), not hardcoded. Measured distribution: `u` 0.71 and `na` 0.55 (Loc vs Acc depends on whether the verb expresses motion) — excluded, since the preposition alone cannot determine the answer; `iz`/`zbog`/`tokom`/`između`/`oko` are 1.00. Computing rather than hardcoding means the thresholds transfer to any other corpus.
- 2026-09-02: Every mined cue states grammatical number, SINGULAR INCLUDED. Genitive singular „želje“ and genitive plural „želja“ are both grammatical after „zbog“, so a bare lemma leaves two defensible answers and would mark one wrong. Precision over prompt naturalness.
- 2026-09-02: Miner dedupes on the RENDERED question, not just (lemma, case). Two sentences differing only in the blanked word produce an identical prompt, which would put contradictory gold answers behind one question. Caught by validate_cloze_dataset during TDD, not by inspection.
- 2026-09-02: Mined items carry `license: CC-BY-SA-4.0`, not the repo default CC-BY-4.0 — CC BY-SA is share-alike and derived items inherit it. Attribution to UD_Serbian-SET is in README.
- 2026-09-02: Mining does NOT address contamination — UD_Serbian-SET is 2010-era SETimes news, long since on the public web. The miner is deliberately corpus-agnostic so the same pipeline can run over freshly tagged recent text, which is the actual contamination fix.
- 2026-09-02: Mined output goes to candidates.jsonl, never items.jsonl — same rule as `generate`. Human-annotated gold lowers the verification burden to a spot-check but does not remove it (a treebank has its own annotation errors, and a second form can be acceptable in the slot).
- 2026-09-02: Added `serbeval synth` — cloze items from authored frames + srLex (CLARIN.SI, CC BY-SA 4.0). This is the contamination answer that mining is not: the sentence is written here, so it provably never appeared anywhere, while the gold form still comes from a lexicon rather than a tagger or a model. Verification drops from per-item to per-FRAME (24 frames vs 519 items).
- 2026-09-02: srLex is NOT vendored (54 MB gz); README links CLARIN.SI. Items derived from it carry CC-BY-SA-4.0, same share-alike reasoning as the mined set.
- 2026-09-02: Synth CAN use `u`/`na`, which mining had to exclude. Mining infers the case from the preposition, which is ambiguous there; synth authors the frame, so the verb fixes motion-vs-rest by construction. Those frames are the deliberate `hard` tier — the distinction models actually get wrong.
- 2026-09-02: Frame classes are semantic ROLES (OBJECT / SURFACE / TOOL), not categories. A single "things" class generated grammatical nonsense („Knjiga je ostala na olovci“, „Otvorio je vrata stolicama“) because what you rest a book on and what you open a door with are different sets. Found by reading generated output, not by unit tests.
- 2026-09-02: Item identity is (question, cue), not question alone — changed in validate_cloze_dataset AND the miner. Template items share one question across many lemmas by design; only a repeated (question, cue) pair is a real contradiction. The old question-only rule would have rejected every synthetic set.
- 2026-09-02: A (frame, lemma) pair is skipped when the frame already contains a form of that lemma — „Stavio je knjigu na ____.“ with lemma „knjiga“ had its own answer („knjigu“) sitting in the prompt. Caught by running validate_cloze_dataset over generated output.
- 2026-09-02: srLex quirk worth knowing: „sto“ exists only as NUM (the numeral hundred), never as NOUN (table). Three other lemmas were simply absent. The synth CLI warns about missing lemmas rather than silently producing a smaller set.
- 2026-09-02: Synthetic candidates go to candidates-synth.jsonl, kept SEPARATE from mined candidates.jsonl. The mined-vs-synthetic accuracy gap on the same phenomenon is an estimate of the contamination effect; merging the files would destroy that measurement.
- 2026-09-02: Added `serbeval check` — a language checker for arbitrary generated Serbian, NOT part of the benchmark. Different problem (find errors in free text with no gold answer) but the same srLex lexicon, so it shares the module rather than duplicating it. This is the one piece usable on production output today, with no API key.
- 2026-09-02: The form index EXCLUDES proper nouns. srLex carries acronyms like „CE“ as PROPN; lowercased into the form set they made „ce“ a known word and silently masked the very common „ce“ for „će“ error. Capitalised tokens are skipped when checking anyway, so PROPN entries add nothing and hide findings.
- 2026-09-02: The ijekavian test requires the je/ije not to be word-initial and the word to be >=5 characters. Without both, „je“ de-jekavizes to the known form „e“ and the copula gets flagged as a dialect marker on essentially every Serbian document.
- 2026-09-02: `data/forms.txt.gz` (3.2 MB, 1.45M forms) IS committed although srLex itself is not. It is one column of an 54 MB file, and committing it is the difference between `serbeval check` working immediately and every user having to download and build first. CC BY-SA attribution in README.
- 2026-09-02: Measured false-positive rate on 8329 words of attested Serbian news: 0.73% with all checks, 0.012% with `--ignore unknown-form`. Nearly all noise is srLex coverage (it lacks „omladine“, „hapšenja“, „biznisa“), not logic — so unknown-form is documented as the advisory one.
- 2026-09-02: Added an `unparsed` metric to every task. Previously a response no answer could be read out of scored 0.0, identical to a wrong answer, so a refusal or a format mismatch was indistinguishable from weak Serbian. Verified through the harness: the dummy model now shows exact_match 0 with unparsed 1.0 on MCQ (no letter readable) and unparsed 0.0 on cloze (readable but wrong) — exactly the distinction that was missing.
- 2026-09-02: Added `srb_grammar_cloze_mined` / `srb_grammar_cloze_synth` task YAMLs over the candidate files. The two run the identical phenomenon over attested vs novel sentences, so the accuracy gap between them is the contamination estimate; they stay separate tasks for that reason.
- 2026-09-02: Added `serbeval baseline` (human worksheet build + score). This is the control that separates "the model is weak" from "the items are broken" — the two hypotheses a low score cannot distinguish. The worksheet never contains gold or explanations, sampling is stratified across tasks (a flat draw over an unbalanced pool leaves small tasks unmeasured), and cloze answers are scored with the benchmark's own `is_correct` so the human and the models are measured on identical terms.
- 2026-09-02: lm-eval 0.4.12's stock `anthropic-chat` adapter cannot evaluate Opus 5 / Sonnet 5 / Opus 4.8 / 4.7 at all — it sends `temperature` (removed on those models -> 400) and reads every response block as block["text"] (KeyError on a thinking block). Fixed by REGISTERING A NEW MODEL NAME (`anthropic-chat-fixed`) in-repo, not by patching site-packages: a pip install must not silently revert it, and keeping the stock adapter reachable allows comparison if a result looks wrong. `scripts/run_eval.py` imports it and delegates to lm_eval's CLI.
- 2026-09-02: The fixed adapter defaults thinking to OFF. Items ask for one letter or one word form; on Opus 5 thinking is on by default and at max_gen_toks=32 would consume the budget before any answer, scoring unparsed across the board. `thinking=adaptive,effort=low` with a large max_gen_toks is available for measuring normal-use behaviour — comparing the two on the same items is worth doing, and costs more since thinking tokens bill as output.
- 2026-09-02: Both adapters drop the tasks' `until: ["\n\n"]`, because the API rejects whitespace-only stop sequences and "\n\n".strip() is empty. Generation therefore runs to max_tokens. Left as-is: the answer is one letter or one word form, max_tokens is small, and both extractors read only the leading part of the response.
- 2026-09-02: Cost measured, not guessed: 1102 items render to 226,261 prompt characters, ~90-125k input tokens per model. At current pricing one full pass over haiku-4-5 + sonnet-4-6 + opus-4-6 is ~$1.50 (worst case ~$2.60); Batch API halves it. Exact counts are free via `client.messages.count_tokens` once a key exists.
- 2026-09-02: Rejected Kie.ai as the eval provider (it does offer an OpenAI-compatible `v1/chat/completions` covering Claude and GPT, so it would have worked technically and sidestepped the adapter bug). For a benchmark an aggregator breaks provenance: you cannot verify which model or snapshot served, whether responses were cached, or whether parameters were rewritten — and a cached response would silently invalidate the repeat-run stability check. Maintainer's call: go first-party.
- 2026-09-10: Added the LICENSE file the project has been missing. `pyproject.toml` declared `license = "MIT"` from the start but no file granted it, so the code was effectively unlicensed — a blocker for publishing regardless of how the eval run turns out.
- 2026-09-10: Data is licensed SEPARATELY from the code, in `data/LICENSE`, because it is not uniform: 130 hand-written items are CC BY 4.0, but 972 items plus `forms.txt.gz` derive from UD_Serbian-SET and srLex and inherit CC BY-SA 4.0. Share-alike is viral — labelling the whole repo MIT would have been a false claim about the majority of the data.
- 2026-09-10: `.claude/` added to .gitignore. It holds the git worktrees; committing it would pull an entire working copy into history.
- 2026-09-23: NO API-backed run could have worked. `pyproject.toml` pinned `lm-eval==0.4.12` without the `[api]` extra, so `tenacity` and `tiktoken` were missing and every API model — the stock `anthropic-chat` adapter included — dies with ModuleNotFoundError. The `dummy` model needs neither, which is why every smoke run passed. Now `lm-eval[api]==0.4.12`, guarded by a test on the declaration.
- 2026-09-23: Claude Opus 5.5 (and Fable/Mythos) reject `thinking: disabled` with a 400 at every effort level, so the adapter's default would have failed every request. Added `thinking=omit` (parameter left out, model thinks adaptively) and a fail-fast check that runs BEFORE lm-eval's own init — a clear error with the exact working command beats 1102 identical 400s in a paid run. Placed first because lm-eval's init failing on the missing extras was masking it.
- 2026-09-23: Whenever thinking is on, max_tokens is floored at 2048. The tasks cap generation at 24-32 tokens for a bare answer; reasoning bills out of the same budget and would exhaust it before the answer, scoring everything unparsed. Consequence recorded in results/README: Opus 5.5 costs ~$3-12 for the full set versus <$1 for non-thinking models; the floor bounds the worst case at ~$45.
- 2026-10-07: Every documented `anthropic-chat-fixed` command would have failed. Without --apply_chat_template, lm-eval passes the prompt as a plain STRING; the adapter put that string straight into `messages` (API 400), and the stock adapter crashes on it outright. The adapter now accepts both shapes (string -> one user turn; list -> leading system message lifted to the top-level `system` field), so the commands no longer depend on remembering a flag.
- 2026-10-07: Kie serves the two triage models in two DIFFERENT formats, neither of them chat-completions: Claude at /claude/v1/messages (Anthropic format, X-Api-Key) and GPT at /codex/v1/responses (OpenAI Responses format: `input`, `reasoning.effort`, text under output[].content[]). lm-eval 0.4.12 has no Responses adapter, so `kie-responses` was added. The earlier suggestion to point `local-chat-completions` at Kie was wrong for these models.
- 2026-10-07: Kie's Claude endpoint defaults `stream` to true (SSE the adapter can't parse); the payload now always sends `stream: false`, which is also the Anthropic API's default, so it costs nothing on the first-party path.
- 2026-10-07: Keys are routed by destination: a base_url on kie.ai reads KIE_API_KEY only and never falls back to ANTHROPIC_API_KEY/OPENAI_API_KEY — otherwise pointing an adapter at a reseller would ship a first-party key to a third party. Covered by a test that plants a decoy OPENAI_API_KEY and asserts it never appears in any request.
- 2026-10-07: First end-to-end test of the real HTTP path: a slow test runs the real lm_eval CLI with both adapters against a local mock of Kie. Every bug so far lived in the lm-eval/adapter seam that unit tests and the `dummy` model cannot reach; this reaches it without spending anything.
- 2026-10-07: `serbeval triage` + scripts/kie_triage.sh: Kie runs are a review aid, never results. Output in results/triage-kie/ (gitignored). Budget: ~230 items/model, ~$1-2 expected, ~$5-6 worst; the GPT endpoint documents no max-output-tokens field, so `reasoning.effort=low` and Kie's prepaid balance are the only caps.
